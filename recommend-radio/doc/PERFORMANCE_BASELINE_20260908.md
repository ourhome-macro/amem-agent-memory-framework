- 真实历史样本：10 条返回 16 个 MMR 候选的首页推荐 Trace。

- 端到端起点为任务事件入库，终点为 SSE `done` 事件入库。
- 测试会话、24 条曝光、3 条 Trace、1 条 L2 场景记忆和 SSE 任务事件均已清理。

## 已完成的性能改造

- 高频推荐表达走规则，模糊表达才进入 LLM Function Calling。
- 画像投影缓存化，并通过 AMEM gRPC 后台刷新稳定快照。
- B 站 Discovery 移出推荐热路径，在线接口只读 CandidatePool。
- L2 场景记忆使用 30 秒本地缓存。
- `shown` 曝光不再同步写入 AMEM，也不触发画像更新。
- Go SSE Gateway 使任务提交约 50ms 返回，后续结果异步推送。
- 推荐 Trace 已补齐候选、MMR、持久化和反馈阶段耗时。

## 优化优先级

1. 候选准入时预计算并持久化歌曲向量，在线只计算 query 向量并在进程内完成 MMR。
2. 将 shown、关键词曝光和 Trace 写入合并成批量事务或 Outbox，移出响应热路径。
3. SSE 从完整 session 快照改为 message/card patch，减少序列化和网络负载。
4. CandidatePool 将 300 条全量读取改为索引粗排后的 32–64 条候选。
5. 对 LLM Router 使用更短 Prompt、结果缓存和超时后的规则降级。
